# news — 繁中新聞 RSS 模組

已完成宣告檔、協定、RSS/Atom 解析與正規化、HTTP Fetcher、前半渲染，
以及協調者／排程：四條 RSS 抓取 worker，啟用模型時另有三條模型 worker 並行處理。
`up` 開始第一輪，抓取結束後隔 10 分鐘下一輪；
抓取中的 refresh 合併成一次待辦。前半提供新聞列表、來源篩選與失敗來源名稱。
v0.2 加入可選的自動新聞分類、類別標籤與來源／類別交叉篩選。
v0.6 加入焦點話題、報導基調、政治議題分析、關鍵字追蹤、閱讀分隔線與近 24 小時風向分段。
完整定稿見 [docs/SPEC.md](docs/SPEC.md)。執行期只用 Python 標準庫與原生 ES module。

## 安裝

需要 Python ≥ 3.12、Expat ≥ 2.6，以及支援 protocol 1 的 modudock。
啟動預檢失敗會在 hello 後回帶 seq 的 fail。公開 repo 由使用者發布；發布後，
在 modudock 主 repo 執行以下指令：

```sh
modudock add https://github.com/gatewen/modudock-news
```

指令須在主 repo 根（有 `.git/` 與 `modules/`）執行，且 `modudock` 執行檔已在 PATH。
安裝登記為 `modules/news` submodule，但不自動 commit、不自動載入；
自行檢查並 commit 登記變更，重啟殼後從 catalog 載入「新聞」。
殼需包含 `4aa95dd` 的後半 publish Topic 修正，否則 `news.fetched` 會被丟棄。
目前 repo 尚未發布，不能把上述模板當成已驗收的安裝 URL。
來源設定在 `back/feeds.json`，不在公開的 `front/` 裡；改完須重新載入模組。

## 分類（v0.2）

在啟動 modudock 殼之前，於殼的環境設定 `TYPESAFE_API_KEY`；殼會將自己的
環境變數繼承給新聞後半。設定或更換 key 後，需讓殼取得新環境並重新載入模組。
key 不寫入模組檔案，也不送到前半或記錄中。

沒有 key 時新聞照常列出，標籤顯示「未分類」，狀態列顯示「分類：關閉」。
有 key 時，列表先顯示，分類完成後補上類別；可同時用來源與類別篩選。
API 回傳 401 或 403 後，本 process 會永久關閉分類，不再嘗試；修正 key 後須重新載入。
429／529 會先短暫等待並重試（詳見下方模型運作說明）；重試仍失敗或其他請求失敗時，
本輪不再開始新的模型請求，已在途的成功結果仍會採納，下一輪再試未完成工作。新聞抓取與顯示照常。

**資料出境提醒：**啟用分類後，新聞的標題＋摘要會送到 TypeSafe AI 的雲端 API，
服務由美國託管；不送連結、來源或全文。分類快取不持久化，殼重啟或模組重載後會重新分類。

## 財經分析（v0.3）

啟用分類後，財經與科技新聞會再分析股市訊號、主要題材，以及對該題材的方向。
切到「財經」或「科技」類別時，列表上方顯示分析面板；範圍是目前來源與類別篩選後的新聞。
面板列出樣本數、來源數、待分析筆數、股市訊號分布、大盤／總經及最多十項題材排行。
不足 10 個事件會提示「樣本少，僅供參考」；未分析或無法辨識的股市訊號計入「未明」。

題材自 v0.4 起按事件數排序；▲／▼ 只計方向機率至少 0.6 的利多／利空。
點題材按鈕可篩選清單，再點同題材或「清除篩選」取消；面板統計不受題材篩選影響。
補送分析結果會保留篩選，切到財經／科技以外的類別則清除題材篩選。
v0.4 面板以事件計數，同一事件多家報導只算一次，樣本行同時保留報導數。
題材清單是人維護的固定表，不會由新聞自動產生新題材；每則只取主要題材。

新增「經濟日報 證券」、「經濟日報 產業」、「MoneyDJ 頭條」、「Yahoo 台股動態」
四個來源，共 13 個來源。合併列表上限提高到 300 則，仍受 900 KB 大小守衛限制。
分析與分類共用 API key 及開關，資料出境與不持久化規則相同。

## 同事件合併（v0.4）

同事件的新聞預設摺疊成一列，顯示最早的一則；點「另 N 則報導」可展開其他
報導的標題、來源與時間，再點收合。來源、類別與題材先篩選個別報導，再摺疊；
代表與其他報導數都依篩選後的內容決定。相同事件 id 的展開狀態會在補送後保留。

後半只比較發布時間相差不超過 36 小時的新聞，標題去空白、標點並轉小寫後，
計算字元 bigram 重疊係數。相似度 ≥ 0.9 直接合併；0.2–0.9 的候選用標題＋摘要
詢問 jev，只有回答同事件且機率 ≥ 0.8 才採納。合併後整群與最早代表的時間差
不得超過 24 小時，避免一路串連成過大的事件。仍可能有少量誤合併與漏合併。
沒有 key 或 API 停用時，仍保留 ≥ 0.9 的自動合併。

財經／科技面板的股市訊號、大盤與題材排行改以事件計數，採用符合來源與類別
篩選、最早且已分析的報導；題材篩選仍只影響清單。樣本行顯示事件數、報導數與
來源數，配對尚未完成時顯示「待合併 X」。配對與分類、分析共用 key、開關及
每輪預算，資料出境規則相同，結果不持久化。

## 國際局勢分析（v0.5）

切到「國際」類別時，原分析面板的位置顯示國際局勢：走向長條依序為升級、僵持、
緩和、無關＋未明；升級使用殼的 danger 色，緩和使用 accent 色，不採股市紅漲綠跌。
清單標籤顯示地區，升級或緩和另加走向文字。

地區列依事件數排序，隱藏事件數為 0 的地區。點選地區可篩選清單，再點同地區或「清除篩選」
取消；補送會保留篩選與事件展開狀態，切換財經／國際面板時清除不適用的篩選。
面板範圍是來源＋類別篩選後的報導，地區篩選不改面板統計；同事件只計一次，
採最早且已分析的符合條件報導。樣本行同時顯示事件、報導、來源與待分析數量。

國際與財經題組分開請求，共用 API key、停用開關與每輪預算。國際只分析國際類別，
每則判斷局勢走向與主要地區；低於 0.35 的題目機率視為未明／其他。仍只送標題＋摘要，
資料出境與不持久化規則同前節。

## 焦點與閱讀工具（v0.6）

類別下拉選單附事件數，例如「財經 97」；依目前來源篩選計算，不受題材、話題或只看追蹤
影響。「全部類別」顯示總事件數，零筆的類別仍可選。來源選單則附各來源的報導數，
失敗來源另標「（失敗）」；「全部來源」顯示本次列表的總報導數。補送會就地更新數字，
保留選取值與選單的鍵盤焦點。

按「↻ 重新整理」後，按鈕立即改成「↻ 更新中…」並暫時停用，清單也向輔助工具標示忙碌。
收到新更新時間的列表就恢復；同一輪的分類或分析補送不會提早解除等待。若 30 秒仍未收到
新列表，按鈕會恢復可按，狀態列顯示「更新未完成，稍後自動重試」，直到下一份列表到來。
原有新聞在等待期間仍可閱讀。

工具列下方的「焦點」整理多家媒體同報的話題，最多五個。話題可以包含同一件大新聞的
不同事件、後續發展與各方反應；右側顯示媒體家數與報導則數。選了來源或類別後，只列出
至少有一則報導符合兩項篩選的話題，但家數與則數仍是整個話題的數字；全部不符合時隱藏。
沒有話題且不在整理中時，焦點改列目前篩選內至少三家媒體同報的事件，點家數可展開其他報導。

點話題的家數按鈕會暫時清除來源、類別與題材／地區／議題篩選，並關掉只看追蹤，進入整個話題。
看完按「返回」或再點同一話題，會還原進入前的篩選、只看追蹤狀態、捲動位置與鍵盤焦點；
找不到的選項或元素會略過。在話題之間切換，仍記住最初的檢視；補送保留話題選擇，
話題消失時也會返回；若使用者已在模組外操作，自動返回不搶走焦點或拉回捲動位置。
手動改來源、類別或按空清單的「清除篩選」，則直接使用新選擇，不還原。

話題中至少五則報導已判斷基調時，標題下方會出現細條與「報導基調」計數：正面、負面、
中性、正反並陳。進入話題後，每列與展開的子報導會各自顯示已判斷的基調，方便對照原文；
篩選列也會列出各來源的報導數，最多五家，其餘以「等 N 家」表示。這些都按報導計數，
基調呈現標題與摘要對事情的評價，不代表民意或事情的真相，也不是股市多空。
話題判斷與基調沿用同一 API key，只送標題＋摘要，資料出境規則同前節。

離開頁面或卸載模組時，會記下本次列表最新的發布時間。下次開啟後，清單開頭連續的新事件
與舊事件之間會出現「上次看到這裡」分隔線，取代每列都標「新」；全部是新的、全部是舊的，
或第一列就是舊事件時不放分隔線。落在後面的零星新事件仍標「新」，焦點區也保留「新」。
同事件只要有一則報導比上次基準新，就算新事件；狀態列的「N 則新」按目前清單的事件數計算，
不是已讀／未讀紀錄。焦點話題另顯示「上次之後新增 N 個事件」，包含已有事件的新報導；
進入話題後可沿分隔線看新進展。第一次使用沒有基準時，不顯示這些標記與新增數。

多報導事件的時間顯示最早到最新的範圍，例如「09:10–11:30」，展開後各則仍顯示自己的時間。
跨日報導顯示日期；當地時間剛好為 00:00 的報導只顯示「今天」或日期，避免把僅有日期的
來源當成午夜發布。清單有摘要時，可按「摘要」在列內展開來源提供的文字，再按收起，
不必只靠滑鼠停留提示。摘要展開狀態不因暫時篩掉或進入話題而清除，只要報導仍在整份列表中，
返回或補送後就會保留；沒有事件 id 且連結為空的報導不記住展開狀態。操作按鈕集中在資訊列右端，
窄版放不下時自然換行；選了特定類別後，列上不再重複類別名稱。

點工具列「追蹤設定」可設定關鍵字，以空白或逗號分隔，按「儲存」或 Enter 套用。最多十個，
每個 1～20 字，不分大小寫去重；標題或摘要包含關鍵字就符合，特殊符號也照字面比對。
事件內任一符合條件的報導命中，代表列會顯示「追蹤：關鍵字」。有關鍵字時，工具列直接
顯示「只看追蹤 N」，按下可與其他篩選並用；N 是目前篩選內符合追蹤的事件數，狀態列不再
重複顯示。沒有關鍵字時隱藏此按鈕；空清單的「清除篩選」也會關掉只看追蹤。

切到「政治」類別時，面板按事件數列出兩岸、美國與國際、國防、選舉、預算與補貼、立法院、
司法、能源環境、地方施政與其他議題，「其他」固定排最後。點議題可篩選清單，再點同議題
或「清除篩選」取消；統計沿用來源與類別篩選，同事件只算一次。政治議題小標只在政治檢視
顯示，面板不顯示方向或近 24 小時風向。這是中立的議題分類，只回答新聞在談什麼，
不判斷藍綠、政黨傾向或支持反對立場；同樣只送標題＋摘要，沿用分類的 key 與資料出境規則。

財經、科技與國際面板多了「近 24 小時」，以列表更新時間為終點，每六小時一段、由舊到新。
同事件只計一次，範圍沿用來源與類別篩選，不受題材／地區篩選影響。財經顯示正面占
正面、負面、正反事件的比例；國際顯示升級占升級、僵持、緩和事件的比例。該段已分析
事件不足五個時顯示「樣本不足」；比例分母為零顯示「—」，只有一至四個時改顯示
「升級 3/3」這樣的計數。這是目前收錄新聞的分布，不是完整市場或局勢的歷史資料。

列表出現後，狀態列用「整理中」表示分類、分析與話題等工作仍在進行，此時不重複顯示未分類數；
若本輪暫停，顯示「整理暫停，下次更新繼續」。整理完成後文字消失；暫停或完成時若仍有未分類，
才列出數量。API 關閉仍顯示「分類：關閉」。尚未產生話題且正在整理時，焦點區顯示
「正在整理多家媒體同報的話題」，新聞仍可照常閱讀。

來源抓取失敗時，狀態列直接顯示來源名稱，例如「中央社 失敗」或「中央社等 2 個來源失敗」。
滑鼠停在狀態列可查看所有失敗來源與各自錯誤的前 80 字。

按鈕的無障礙名稱與畫面上的文字一致，方便語音操作；篩選用途、利多／利空或升級／緩和
數量等補充資訊另提供給螢幕閱讀器，不用箭頭符號代替說明。

### 模型如何運作

啟用模型時，以三條 daemon worker 共用同一 key，同時最多處理三個模型請求。空出的 worker
依「分類 > 配對 > 話題 > 分析 > 基調」挑選待辦，讓焦點話題較早出現；同一種工作也能多批並行。
這是取新工作的優先序，不會中斷已送出的請求，也不保證回應順序。話題仍須等事件配對完成後才排入。

每輪各類模型工作共用 60 秒准入預算：期限後不開始新請求，已在途的請求可完成並補送結果。
同一種工作中，已在排隊／處理的報導或配對不重複送問；任一批失敗後停止本輪新請求，其他在途的成功結果
照常接收。401／403 會永久關閉本 process 的所有模型工作，重新載入才能再試。

API 回傳 429／529 時，在同一請求的總讀取期限內，依序等待 0.5 秒、1 秒，最多重試兩次
（含首次共三次）。預設總讀取期限為 30 秒，重試不重設期限；剩餘時間不足就停止。
401／403 不重試，限流記錄只寫固定提示，不含回應內容或 key。沒有 key 時不啟動模型 worker，
四條 RSS 抓取 worker 仍照常工作。

### 本機儲存

前半使用瀏覽器 localStorage 保存兩項資料：

- `modudock.module.news.lastSeen`：上次列表的發布時間基準，供閱讀分隔線、「新」標記與話題新進展計數使用。
- `modudock.module.news.watch`：追蹤關鍵字清單。

兩項都只存於本機瀏覽器，不送往分類 API；清除網站資料會一併清掉。瀏覽器禁止儲存或
資料損壞時，新聞仍可閱讀，但設定可能無法保留。新聞內容與分類、分析、事件、話題及
基調快取仍不持久化，重新載入模組後會重新取得或判斷。

## 本機開發

工作副本放在 `/Users/gatewenlee/Code/modudock-modules/news`，目錄名就是 id。
殼只掃真目錄，不能以 symlink 代替。

```sh
cd /Users/gatewenlee/Code/modudock/shell
go run ./cmd/modudock -addr 127.0.0.1:8731 -modules /Users/gatewenlee/Code/modudock-modules
```

瀏覽器開 `http://127.0.0.1:8731`。模組 repo 內執行：

```sh
/usr/local/bin/python3 -m unittest -v
npm ci --ignore-scripts
npm test
./scripts/dev-check.sh
```

dev-check 需要 Go 與提供內建 WebSocket 的 Node，會起自己的殼、連 `/ws` 比對
完整 catalog 宣告，再關閉自己的 process group；8731 已占用時拒絕執行。
此檢查不等於瀏覽器掛載驗收。協定測試使用真 subprocess；
`NEWS_TEST_DIR`、`NEWS_TEST_MODE`、`NEWS_TEST_FEEDS`、`NEWS_TEST_SCHEDULER`、`NEWS_TEST_JEV_URL`
僅供測試注入及 writer 閘門，
正常執行請勿設定；宣告檔沒有啟用它們。

`back/fetch.py` 的 `Fetcher.fetch(url, validators)` 回傳 `Result`，status 為
`ok` / `not_modified` / `error`。validators 使用 `etag`、`last_modified`；成功取得
只回候選值，不代表 XML 解析成功，也不提交快取。`timeout`、`deadline` 可在測試縮短。
`news.py --allow-host HOST` 可重複，只配置 Fetcher 的精確主機放行名單；收到 up 才抓取。
正式宣告檔不帶此參數。User-Agent 帶 repo 網址 `https://github.com/gatewen/modudock-news`。

前半由三個相對 import 的原生 ES module 組成：`front/front.js` 負責掛載、狀態與互動，
`front/style.js` 保存樣式字串，`front/labels.js` 保存名稱對照、分析驗證與無狀態工具。
三檔都在 manifest 的公開目錄 `front` 內，不需要打包。

協調者接住 `fit_packet` 的 `ValueError` 並記 stderr，該輪不送 list/publish、仍算結束；
304 無快取標失敗並清 validators，解析失敗不提交 validators，失敗保留 stale items。
RSS 抓取 worker 只回候選；協調者驗輪 id 與期限後才整份提交 items/validators/first_seen。
每來源採納期限由 worker 取件時計起；尚在排隊的來源由整輪期限兜底。

### 已知限制

執行期不需要 npm；happy-dom 只用於開發測試。已知限制：

- 不防 DNS rebinding（解析與連線會是兩次查詢）。
- 四條 RSS 抓取 daemon worker 可能被慢 headers、慢 body 或 DNS 佔住，不能強制回收；
  全部占用時停止更新，每輪回報 deadline，直到連線自行結束。
- 三條模型 worker 的總讀取期限在每次讀取前後檢查；DNS、慢 headers 或單次阻塞讀取
  仍可能超過期限，不能強制中斷。停止模組不等待被網路卡住的 worker，維持原有退出政策。
- 新聞與 API 結果快取不持久化；殼重啟或模組重載後重新取得。前半兩項本機設定見上節。
- stdout 堵塞時 done 盡力送；等待 0.8 秒後強制退出，優先維持 1 秒退出政策。
- Python 的 CA store 可能是空的（例如 python.org macOS 安裝未裝憑證）。Fetcher
  先用預設 SSL context；若無 CA，依序嘗試 SSL_CERT_FILE、macOS/Debian/RHEL
  常見系統 bundle。仍無 CA 時 HTTPS 回報 `no CA certificates`，不連線、不關驗證。
  系統必須提供可信且有效的 CA bundle；修正憑證後須重新載入模組。

### 刻意不做（SPEC §9）

- 全文抓取、圖片、歷史新聞搜尋、使用者自訂來源 UI、新聞與 API 結果持久化、通知。
- GitHub 發布由使用者處理；公開 repo 發布後才做 `modudock add` 安裝驗收。
